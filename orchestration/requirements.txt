# Installed into the Airflow environment. dbt is NOT installed here -- it lives
# in its own virtualenv, built separately in the Dockerfile.
#
# Note there is deliberately no [dbt-snowflake] extra on astronomer-cosmos. That
# extra installs dbt-core and dbt-snowflake into the Airflow environment, which
# defeats the point of the separate venv and makes the dependency graph
# effectively unsolvable: Airflow and dbt pin overlapping, mutually incompatible
# ranges of protobuf, jinja2 and packaging, so pip backtracks through thousands
# of version combinations and eventually dies with ResolutionTooDeep. Cosmos does
# not need dbt importable -- it shells out to the binary at dbt_executable_path.
#
# Pinned exactly rather than as ranges. A range lets pip explore every release in
# it before settling, which is slow at best and the difference between a working
# build and a failing one at worst.
#
# The provider pin is chosen against the Airflow version in the base image, not
# against the newest release. astro-runtime:12.7.1 constrains
# apache-airflow==2.10.5, and every apache-airflow-providers-snowflake from 6.7.0
# onward requires apache-airflow>=2.11.0 -- so "latest" is unsatisfiable here and
# 6.6.1 is the newest version that fits. Moving to a newer provider means moving
# the base image first, in that order. Pinning a dependency without checking what
# the platform underneath it already pins is how this kind of build breaks.
astronomer-cosmos==1.15.0
apache-airflow-providers-snowflake==6.6.1
